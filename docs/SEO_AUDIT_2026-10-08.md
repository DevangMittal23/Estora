# Estora technical SEO audit — 8 October 2026

This audit starts from commit `49d459f`, after the previously approved public features and SEO foundation. This request is a new local review: no commits, staging or pushes are authorized.

## Architecture and original findings

The existing frontend is React 18/Vite 6 with React Router 6 and React Query, not Next.js. Public content already renders through a Vite SSR entry and Vercel Node Function, then hydrates in anonymous browsers. Account routes retain the existing SPA/authentication renderer. Express/Mongoose serves the API separately on Render. The production canonical origin remains `https://estora-pi.vercel.app`. The alternate Netlify configuration is a static SPA fallback and does not provide the Vercel document renderer.

Public inventory: homepage, marketplace, published property detail slugs, fractional ownership guide, About, Insights index and three published articles, calculator directory and two calculators, and the single meaningful Lucknow landing page. Account inventory: login/signup/recovery, investor/broker/admin route families, profile and notifications. There is no existing Contact route, so no empty Contact page is being invented.

Existing strengths: actual LIVE/FUNDED-only public projection, stable property slug/ID URLs, private media permission checks, server titles/canonicals, dynamic sitemap, robots, Organization/WebSite/Breadcrumb/Article JSON-LD, WebP assets, lazy account/chart modules, local WOFF2 fonts, reduced-motion styles and preserved Vercel Analytics with URL privacy controls.

Gaps found before editing:

- Browser head updates duplicate the server tag logic, omit image alt/article metadata, and can retain stale social fields after navigation.
- Password-reset URL tokens are echoed in the private shell's serialized pathname even though no public property data is rendered there.
- A public HTTP failure can have its noindex metadata overwritten by the browser's static-page metadata.
- Public query data is unnecessarily invalidated immediately after hydration on every public page; property-detail refresh is needed for existing permission-checked documents, but catalogue/stat snapshots are already freshly fetched.
- Homepage property and stats API reads are sequential; static education pages use no-store despite containing no personalized data.
- Sitemap generation does not validate pagination metadata or deduplicate input URLs, and its standalone serializer accepts invalid property identifiers. Preview sitemaps unnecessarily read the API before removing property records.
- Login/signup/recovery are both disallowed and noindex, preventing crawlers from observing their noindex instruction.
- Repeated slashes/encoded unreserved characters and public path casing are not normalized consistently. Development middleware bypasses unknown file-like paths and can fall through to an inappropriate SPA success response.
- Editorial hero images omit intrinsic dimensions/loading hints, fallback property-image alt text can imply an actual photo, and social imagery uses a generic alt description.
- Property metadata omits useful existing location/type/minimum-commitment data. Several static snippets do not reflect the actual free tools and guide topics as clearly as they could.

Public production robots and sitemap responded HTTP 200 during the initial audit. Full production indexing, Search Console ownership and field Core Web Vitals are not inferred from those responses.

## Implementation and validation — completed locally on 9 October 2026

### 1. Original SEO issues

The findings above were verified against the starting code. The website already had public SSR and a substantial SEO foundation; this change strengthens that implementation rather than replacing the application. There was no need to create another router, generate additional articles/cities, install a metadata library or alter the backend.

### 2. Improvements implemented

Server-rendered and browser-updated metadata now share one tag definition. Optional article/image fields are removed when navigation makes them irrelevant. Public error documents retain noindex after mounting, and loading property data is distinguished from a missing property. Private document state omits the route pathname so password-reset tokens are not echoed into HTML.

Static and dynamic snippets were rewritten from the actual page content. Public path casing, repeated/trailing slashes and percent-encoded unreserved characters resolve to preferred paths. Case-sensitive reset tokens and encoded path separators are preserved. Missing file-like document routes now receive a real development 404 rather than an SPA success response. Production function failures include noindex, no-store and Retry-After.

New regression coverage tests DOM metadata across navigation; additional server tests cover privacy, URL normalization, sitemap pagination/failures, public edge caching and parallel read-only homepage requests. This report is the other new file. No new runtime dependency was added.

### 5. Sitemap

`/sitemap.xml` continues to render dynamically through the SEO document handler. It includes the public route registry, published articles and all paginated LIVE/FUNDED property records from the existing read-only public API. Records are validated, invalid IDs/drafts are excluded, and duplicate property IDs are collapsed. Only canonical HTTPS URLs are emitted; no query filters, private routes or private documents appear. Article/property lastmod is included only when the actual date parses successfully; static pages receive no invented dates.

Malformed or unavailable API pagination returns a retryable 503 instead of a partial or fabricated sitemap. Preview sitemaps are noindex and never fetch/include properties. The current single-sitemap ceiling remains 50,000 URLs; a sitemap index is required if the site grows beyond it.

### 6. Robots

`/robots.txt` allows public content, identifies `https://estora-pi.vercel.app/sitemap.xml`, and excludes the actual admin/broker/investor/profile/notification/reset/API paths. Login, signup and forgot-password entry pages are crawlable so their noindex can be observed. Google requires crawl access to discover a robots meta instruction; a robots block alone is not a privacy or deindexing mechanism. [Google robots meta documentation](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag).

Vercel previews retain `Disallow: /` plus document noindex. Existing authentication and media permissions remain the security boundary.

### 7. Canonicals and duplicate URLs

Canonicals use `https://estora-pi.vercel.app`. Server HTML and client navigation agree. Tracking parameters do not become new canonical pages. Marketplace query combinations are noindex with the base marketplace canonical; normal UI filters still work and do not generate new indexable route families. Public casing/slash/encoded-unreserved variants redirect 308. Legacy/stale property slugs redirect 301 to the actual current stable-ID slug; `/index.html` redirects to `/`. Unknown public documents/properties/articles/cities return 404 and noindex; public data outages return 503 and Retry-After.

### 8. Structured data

- Organization on homepage and About, using the actual name, domain and public vector logo; no invented address, registration, social account or contact.
- WebSite on the homepage.
- BreadcrumbList on public hierarchical pages, with labels matching visible breadcrumbs.
- Article on the three existing published articles, with actual organizational author, category, dates, description and image. The organization author links to About. No fabricated person, review, rating, Product offer or financial return schema was added.

JSON-LD remains safely escaped. Article fields follow the actual editorial record, consistent with [Google's Article documentation](https://developers.google.com/search/docs/appearance/structured-data/article).

### 9. Metadata and content semantics

Every locally published sitemap page has a unique title and description, canonical, index/follow directive, Open Graph and Twitter image/title/description metadata. Language remains `en-IN`; the existing favicon is preserved. Known illustrative image dimensions and meaningful social image alt text are supplied. Article publication/update/category tags are removed when leaving an article; unverified dimensions are omitted for property images.

Property snippets use the actual name, location, type, funding state and minimum unit commitment when available. Minimum amounts use safe integer paise with BigInt multiplication; absent or overflowing values are omitted. Signed/private/credential-bearing imagery is rejected, including encoded private/signed URL segments. No ROI, rental yield, valuation or regulatory claim is invented.

All checked public documents render one primary H1 in real HTML without requiring JavaScript. Existing semantic navigation/main/footer/sections, heading structure, keyboard styles and article text are retained. Public property-type/status dropdowns now have explicit accessible labels. Calculator pages add one natural link to compare published properties; the existing guide/article/marketplace links remain available.

### 10. Image SEO

The guide, About, Insights lead and article hero retain their existing WebP image and crop while gaining intrinsic dimensions, eager loading and asynchronous decoding. Scoped automatic height preserves their existing responsive geometry. Below-the-fold resource illustrations remain lazy. Existing property image priority/reserved dimensions and private-media permission handling remain intact. Missing/broken property-image fallback alt text now identifies illustrative architecture instead of implying an actual photo.

No image was replaced or removed. Existing local image files, compression and responsive CSS are preserved; no unverified transformation was applied to permission-checked media URLs.

### 11. Performance

Independent homepage property/stats reads now start together. Fresh public catalogue/stat snapshots no longer immediately refetch after hydration; a Chrome check confirmed zero redundant homepage property/stats browser requests. Property-detail refresh remains narrowly scoped to preserve existing interactive, permission-checked documents.

Only build-owned, non-personalized editorial HTML receives a short shared-edge cache header. Properties, marketplace, city data, private documents, errors and previews remain no-store. Homepage hero and the two actually used editorial fonts are preloaded. Existing font-display: swap, lazy account/chart chunks, reduced-motion styling and Vercel Analytics are preserved.

Final browser entry: 496.33 kB / 155.55 kB gzip. Charts remain in a separate lazy chunk. This work does not claim a smaller JavaScript bundle, measured field Core Web Vitals or an arbitrary Lighthouse score.

### 12. Intentionally noindex

Login, signup, forgot-password, both reset URL families, all investor/broker/admin application routes, profile, notifications, forbidden/error routes, missing public pages, failed data documents, marketplace query/filter combinations and Vercel previews. Private pages have no public canonical or JSON-LD, do not render private account data server-side, and remain guarded by the existing application authentication. No sensitive state is added to public property snapshots, metadata or sitemap output.
